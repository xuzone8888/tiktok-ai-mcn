Phase 1: UI/后端代码改造
================================================================

--------------------------------------------------------------
1.1 隐私级别选择器 — 改为无默认值 + 动态选项   [P0]
--------------------------------------------------------------

  TikTok 要求：禁止预选默认值，选项必须来自 creator_info 的 privacy_level_options

  当前代码状态：
  - PublishSettings.tsx 第 51-56 行：使用静态 PRIVACY_OPTIONS 数组
    4 个按钮始终高亮一个（有默认值）
  - publish-processor.ts 第 319 行：privacy_level 硬编码 fallback 到 SELF_ONLY

  需要改的：
  ① 将 4 按钮改为 <Select> 下拉框，初始为空（placeholder = "请选择可见范围"）
  ② 选项列表从 creator_info API 动态获取
  ③ 移除 SELF_ONLY 硬编码 fallback
  ④ 未选择时禁用发布按钮
  ⑤ 后端校验：如果前端未传 privacy_level，后端直接返回 400 error
     绝不静默补默认值

  涉及文件：PublishSettings.tsx, publish-processor.ts, publish/page.tsx
  验证方式：浏览器检查 → 隐私下拉框初始为空 → 未选时发布按钮灰色

--------------------------------------------------------------
1.2 互动开关 — 新增 Comment/Duet/Stitch 并默认关闭   [P0]
--------------------------------------------------------------

  TikTok 要求：必须有 Comment/Duet/Stitch 三个开关，默认全部 unchecked

  当前代码状态：
  - PublishSettings.tsx 中完全没有互动开关
  - content-posting.ts 第 19-21 行已有字段定义

  需要改的：
  ① 新增 3 个 Toggle/Switch（Allow Comment / Allow Duet / Allow Stitch）
  ② 默认值必须为 false（关闭状态）
  ③ 如果 creator_info 返回 comment_disabled=true 则灰化该开关
  ④ 相同逻辑应用于 duet_disabled 和 stitch_disabled
  ⑤ 前后端 state 打通到 API 请求

  涉及文件：PublishSettings.tsx, publish/page.tsx, publish-processor.ts, content-posting.ts
  验证方式：3 个开关默认关闭 → 手动开启 → 发布后检查 API 请求体

--------------------------------------------------------------
1.3 商业内容披露组件 — 全新组件   [P0]
--------------------------------------------------------------

  TikTok 要求：必须有 Content Disclosure 开关 + Your Brand / Branded Content 子选项

  当前代码状态：
  - 前端完全没有此组件
  - 后端 content-posting.ts:98 已有 brand_content_toggle 字段

  需要改的：
  ① 创建新组件 ContentDisclosure.tsx
  ② Content Disclosure 主开关（默认 OFF）
  ③ 开启后展示两个子选项：Your Brand / Branded Content
  ④ 选中 Your Brand → 提示 "Promotional content"
  ⑤ 选中 Branded Content → 提示 "Paid partnership"
  ⑥ 开关开但未选子选项 → 禁用发布按钮 + 悬停提示
  ⑦ Branded Content + SELF_ONLY 冲突处理：
     禁用隐私下拉中的 SELF_ONLY 选项，灰化 + hover 提示
     "Branded Content cannot be set to private"
  ⑧ 映射 API 字段：
     Your Brand → brand_organic_toggle=true
     Branded Content → brand_content_toggle=true

  涉及文件：新增 ContentDisclosure.tsx, 修改 PublishSettings.tsx, publish/page.tsx
  验证方式：所有 6 种组合状态逐一验证

--------------------------------------------------------------
1.4 用户同意声明 — 发布按钮前   [P0]
--------------------------------------------------------------

  TikTok 要求：发布前必须展示法律声明文本（含可点击链接）

  当前代码状态：完全没有。搜索 "Music Usage" 零结果

  需要改的：
  ① 在发布按钮上方添加声明文本
  ② 根据商业披露状态动态切换文案：
     - 普通/仅 Your Brand →
       "By posting, you agree to TikTok's Music Usage Confirmation"
     - Branded Content (含同时选中) →
       "By posting, you agree to TikTok's Branded Content Policy
        and Music Usage Confirmation"
  ③ 链接可点击

  涉及文件：publish/page.tsx 或新增 ConsentStatement.tsx
  验证方式：不同披露状态下声明文案自动切换，链接可点击

--------------------------------------------------------------
1.5 AIGC 标识修复 — is_aigc 默认值改为 true   [P0]
--------------------------------------------------------------

  TikTok 要求：AI 生成内容必须标记 is_aigc: true

  当前代码状态：
  ⚠️ content-posting.ts:100 写的是 is_aigc: postInfo.isAigc ?? false
  默认值为 false，不正确！ToryX 是 AI 创作工具

  需要改的：
  ① 将 ?? false 改为 ?? true
  ② 前端发布页保持 isAigc: true 传值
  ③ 可选：前端加 "AI Generated Content" 标识提示

  涉及文件：content-posting.ts, publish-processor.ts
  验证方式：代码审查 + 日志检查 API 请求中 is_aigc: true

--------------------------------------------------------------
1.6 创作者信息展示 — 发布页头像+昵称   [P0]   ↑ 从 P1 升级
--------------------------------------------------------------

  TikTok 要求：发布页必须显示目标账号的昵称和头像（Required UX，非加分项）

  当前代码状态：
  - getCreatorInfo() 已实现，返回 creator_avatar_url、creator_nickname
  - 但发布页 UI 未展示

  需要改的：
  ① 发布页加载时调用 creator_info API
  ② 在发布设置区域顶部显示创作者头像+昵称
  ③ 加载失败时显示错误提示

  涉及文件：publish/page.tsx, 可能需要新 API route
  验证方式：发布页加载后显示 TikTok 头像和昵称

  ⚡ 优化设计：creator_info 是多个功能的数据源
     （隐私选项1.1、互动禁用1.9、发布上限1.7、时长1.8）
     建议设计为统一的 creator_info 数据获取层，一次调用多处复用
