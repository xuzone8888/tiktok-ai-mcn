# Star Gaze 平台化升级规划(2026-07)

> 产出方式:代码仓库摸底 + 竞品联网调研 + 各平台 API 政策核实(2026-07)+ 产品架构/MCP 平台化/商业化三视角设计 + 红队与评审对抗审查后的综合裁决版。

---

## 〇、一句话结论

**Star Gaze 的定位不是"内容生成网站",也不该直接宣称"All-in-One 平台",而是:中国团队合规触达海外流量的整条管道——AI 矩阵内容工厂 + 官方 API 发布中台。** 生成是获客钩子,发布+数据是留存和毛利,MCP/Agent 是第二曲线,私域转化是远期叙事。

三步走:
1. **0–3 月**:TikTok 矩阵闭环能收钱,风控先于收钱,长周期审批全部前置提交;
2. **3–6 月**:统一数据模型 → 收编 YouTube/Meta → 数据回流,多平台+数据看板成为留存钩子;
3. **6–12 月**:评论聚合半自动化、WhatsApp 追踪短链轻集成、MCP 对 3–5 家共建客户开放。

## 一、现状判断:三个关键事实

### 1. 你真正的资产不是功能数量,而是三样东西

代码摸底结论:全站最重的模块是 video-batch(4246 行,多模型批量生成流水线)、TikTok publish+accounts(约 5800 行,多账号×多素材矩阵发布+定时+重试)、角色体系(ai_models+contracts)。再加上一套竞品没有的跨境工程:美国 OAuth broker、CN/海外发布双栈、出口隔离。

**真实资产 = TikTok audited 发布权限(稀缺,unaudited 只能 5 用户/24h 且强制私密可见)+ 跨境合规工程 + 批量生成引擎。** 其余板块多为半成品:templates 仅 189 行占位;viral-clone 后端完整(5 表+事件表)但没有导航入口;link-video/image-slideshow 成片后是死胡同,不连发布;FB/IG 页面是 15 行薄壳;数据回流仅 TikTok 有代码且被 feature flag 关闭;无评论、无线索、无对外 API。

### 2. 市场:两头红海,中间有空位,最危险的对手是字节 Pippit

- **纯 AI 视频生成已红海**:HeyGen ~$95M ARR 领跑,Creatify/Topview/Arcads 挤满电商带货赛道,字节 Pippit(CapCut 系)免费提供"链接生成视频+自动发布 TikTok/FB/IG+分析"——与 Star Gaze 形态最像,且背靠字节。单点做生成没有胜算。
- **纯排程发布在打价格战**:Buffer/Metricool/Publer $4–22/月。
- **结构性空位**:①"生成→合规矩阵发布→数据→线索"的闭环没人打通(Pippit 无矩阵无私域,GoHighLevel 无 AI 内容无 TikTok,respond.io 无内容);②中国团队的合规出海矩阵发布——蚁小二/易媒靠客户端模拟,封号风险高,官方 API 是代差;③社媒发布的 MCP/Agent 基础设施"早期、混乱、无生产级方案"(Blotato/Postiz/Ayrshare 各有残缺,X 已上官方 MCP),窗口存在但在收窄。
- **中国团队典型死法**:群控/非官方接口被风控一夜归零;功能杂货铺被垂直头部逐个碾压;主体/收款/合规拖死;模型套壳被字节免费产品降维。

### 3. 最大的风险不是竞争,是"平台权限连坐"和"官方限额与客户预期的落差"

- TikTok audited 权限挂在**你的** App 主体上。任何一个矩阵客户批量发同质垃圾内容,吊销的是全平台所有客户的能力。你要服务的恰恰是最会踩线的人群(正在用群控的 MCN)。**风控体系必须先于收钱上线,这是本方案对原路线最大的修正。**
- 官方 API 限额:TikTok 每创作者约 15 帖/24h(全部第三方 API 共享),App 级"日活跃创作者上限"由审核核定;IG 50 帖/24h;YouTube videos.insert 已于 2025-12 从 ~1600 降至 ~100 units(默认配额下每天可发约百条,利好),但未过 compliance audit 的项目上传视频**锁 private**。习惯群控日发几百条的团队,官方 API 是"降级体验"——**定价前必须先拿 3 个真实矩阵团队在官方限额下跑 4 周,验证发布量/封号率/留存,再定价。**

## 二、定位:三层战略

| 层 | 定位 | 时点 | 说明 |
|---|---|---|---|
| **A(首发)** | 中国出海团队的"矩阵内容工厂 + 合规发布中台" | 现在 | 对标蚁小二但走官方 API,对标 Pippit 但做矩阵多账号;客群付费意愿明确,现有代码匹配度最高 |

## 三、产品架构重组

### 3.1 信息架构:七八个创作入口收敛为一条主轴

**资产 → 创作 → 内容库 → 发布 → 增长**,五个一级板块 + 账户区。

**① 角色与资产**:角色创建 + 角色市场 + contracts 保持独立。角色是可复用资产,不是创作流程的一步。

**② 创作 Studio**(两个工作台 + 参考导入):
- **图片工作台**:quick-gen(单图)、image-batch(批量)、image-factory(商图精修)合并为一个页面的三种模式——三者共用"选角色/模特 + Prompt + 出图 + 历史"骨架,不需要三套 UI;商图精修成为其中的"电商模式"标签页。
- **视频工作台**:以 video-batch 为唯一引擎。image-slideshow 砍掉独立页,降级为一种输入轨("图片序列→视频")。
- **参考导入**(link-video 与 viral-clone 合并):两者本质相同——"参考物驱动创作"。贴链接=解析商品/文章出脚本分镜;传视频=逐段克隆重生成。产物统一注入视频工作台,**不再各自带成片和发布出口**。viral-clone 后端已完整,补入口转正(它是矩阵客群的刚需卖点),但放出前必须先解决版权红线(见 §8)。
- **模板中心**:短期从导航隐藏(现在只是 189 行占位,留着损害产品可信度);6 个月后升级为"工作流市场"——模板重定义为**可执行配方 = 输入槽位 + 脚本结构 + 分镜配置 + 模型参数 + 发布预设**,link-video 的 5 步向导就是现成的模板运行时。
- **砍掉**:meta-publish 占位页、边缘化的 projects/task_queue 旧表;video-batch 直连各模型的专用端点收编进统一 models/submit 网关(消除生成双轨)。

**③ 内容库**:assets 从"生成记录归档"升级为**待发内容池**。卡片=Content,状态流转 draft→ready→scheduled→published,按项目/标签/类型筛选,每卡一个「分发」按钮。

**④ 发布**:账号中心(全平台统一,分组+健康度+token 预警)、发布队列(矩阵编排器:N 内容 × M 账号组生成 Post 网格,每格可单独改标题/话题/挂车)、排期日历(拖拽改期,频控提示)。

**⑤ 增长**:数据总览 + 评论聚合 + 线索列表。

**衔接铁律:创作板块完成态只有一个动作「入库」;「发布」按钮只存在于内容库和发布板块。** 这一条执行到位,三条用户路径(漫剧批量做剧集、电商从链接到询盘、MCN 矩阵混剪排期)的断点就全部接上了——摸底确认的断点全部是"创作完成后进死胡同,得下载再手动上传"。

### 3.2 对象模型:从"任务中心"改为"作品中心"

现状:五套任务表并行(quick_gen_history / ecom_image_tasks / link_video_jobs / viral_clone_* / 四套 publish_tasks),无统一聚合,**这种私有实现细节根本无法对外暴露成 API**。

目标模型:

```
Workspace(团队,两级角色:管理员/成员+账号可见范围)
 └─ Project(项目,通用分组,不引入 Episode 概念)
     └─ Job(统一生成任务表,type 区分图/视频/克隆)
         └─ Content(作品,generations 升级;状态 draft→ready→published)
Account(四平台统一,platform 字段+分组+健康度)
Post = Content × Account(发布实例,携带 scheduled_at/状态/metrics)
Lead ← Post 的评论/短链点击(归因链:Lead→Post→Content→Project)
```

**Job 是过程,Content 是资产,Post 是分发实例**——三者分离后 Web/App/API 三端消费同一套对象:App 只订阅 Account/Post/Lead 的变化流;MCP 动词天然落在对象上(create_job / publish / get_metrics / list_leads)。

**迁移策略(评审裁决)**:0–3 月不迁旧数据,但**立即冻结旧表结构、定义新 posts 表,所有新功能只写新表**;3–6 月收编 YouTube/Meta 时落点就是新表,避免二次返工。

## 四、数据闭环:发布工具没有数据回流就是一次性工具

最小闭环三件事(也是 App 和获客 Agent 的数据地基):
1. TikTok sync-stats 打开——**先决条件:与 TikTok 确认审核状态,审核未过则整体顺延**(这是红队发现的方案内自相矛盾处,以此为裁决);
2. IG webhook 从"验签打日志"补成落库(comments 表);
3. WhatsApp Link 换成自有域**追踪短链**,点击即产生 Lead——这是"客户线索"的最小可用定义,不需要任何平台私信权限。

数据总览先做四张表:**内容榜**(什么内容有效,按项目/模板分组)、**账号健康**(发布量/涨粉/token/失败率)、**发布漏斗**(生成数→入库→发布成功率→均播,暴露链路损耗)、**线索表**(来源 Post/平台/联系方式/状态)。

## 五、AI Agent 与 MCP:现实版路径

### 5.1 四个场景按可行性重排

| 场景 | 可行性 | 现实版 |
|---|---|---|
| 矩阵账号运营 | **可做,第一个对外故事** | 批量生成+多账号排期发布全部已有,补数据回流即闭环 |
| AI 内容运营 | 可做 | DeepSeek 脚本/多语言已接;先做 2–3 个硬编码 pipeline("选题→脚本→成片→排期"),不做通用工作流引擎 |
| 跨境获客 | **打折落地** | 全自动回评拿不到(TikTok 普通号评论 API 不开放,仅 Business API 另行资质);打折版=评论聚合(先 YT+IG)→ AI 建议回复 → **人工一键发送**;线索用 wa.me 追踪短链,不用 API 主动发信 |
| 海外客服 | **暂缓,不立项** | 本质是 WABA 客服独立产品,与现有能力几乎零复用;且 WhatsApp 已宣布 2026-01-15 起禁止通用型 AI 聊天助手,政策方向不利 |

### 5.2 平台化的正确做法:内外同一套

- **工程规范(不单独立项)**:route handler 薄壳化,把批量提交/排期发布/precheck 下沉为 `lib/services/*` 纯函数(输入=未来 API 的 DTO,输出=job 对象),站内页面与未来 REST/MCP 调同一函数。验收标准:MCP 上线时零新业务代码。
- **异步建模**:所有长任务返回 job 对象 `{job_id, status: queued|running|succeeded|failed|review_pending, progress, result_asset_ids, credits_charged}`;MCP 用 get_job/wait_job(≤60s)轮询,REST 供 HMAC 签名的出站 webhook。
- **第一版 MCP 工具(6–12 月,仅对共建客户)**:list_characters / generate_image / generate_video / get_job / list_assets / list_accounts / create_publish / get_publish_stats(标 beta)/ get_credits。**run_workflow 移出第一版**(templates 还是空壳);评论/私信/WhatsApp 发送/提现不进——权限未到手,承诺即空头 API。
- **平台自保机制(命根,先于收钱)**:先审后发(moderation 不过或新租户首 N 条停在 review_pending);内容相似度去重+矩阵编排器**内置强制变体**(标题/封面/时长抖动——各平台按"协同不实"处置同内容批量分发,这必须做成功能而不是免责声明);配额三层(租户/日、账号/日=官方限额的 70%、平台级熔断);账号健康分驱动降配额→冻结;平台删帖回执回写并自动降级租户。**宁可误杀限流,不可让单租户烧掉平台主体的 API 权限。**

## 六、商业化

### 6.1 用户收敛:前 12 个月只服务两类人

**打**:① 国内做 TikTok 出海矩阵的内容制作公司/MCN(video-batch+矩阵发布+角色体系就是为他们写的;单客月耗 2000–8000 元合理);② 跨境电商内容团队(TikTok Shop 方向,shop-publish/商图精修/链接生成天然对口,付费由 GMV 驱动,获客渠道与①重合)。

**不碰**:中小企业营销团队(需求泛、客单低)、海外客服/私域企业(另一个产品)、个人创作者(付费弱、客服成本高)、漫剧团队(垂直工作流未建,templates 是占位,别接)。

### 6.2 定价:积分做计量底层,订阅做收入底盘

| 档位 | 定价 | 包含 |
|---|---|---|
| 创作版 | ¥499/月 | 约 ¥600 等值积分、3 个 TikTok 账号、单席位 |
| 矩阵版 | ¥1,999/月 | 约 ¥2,600 等值积分、20 账号、批量+定时发布、3 席位 |
| 工作室版 | ¥6,999/月 | 约 ¥10,000 等值积分、100 账号、子账号权限、数据看板、专属支持 |
| 加购积分 | 现有充值包 | 订阅客户 9 折 |

**毛利纪律**:
- 积分价格按模型分级,**每模型积分定价 ≥ API 成本 × 2.5**(现有 registry/adapter 正好支撑分级计价);定价页写明"随上游成本调整";失败退积分但限重试次数;设单客户日成本熔断。
- 发布/排期/账号管理/看板边际成本近零,**全部锁进订阅门槛**——生成赚 60% 毛利,发布赚 90%+;毛利叙事的重心放在发布订阅,生成按成本浮动透传(Pippit 免费已把生成端价格锚死)。
- 中转商(速创/高瑞)是流沙:核心模型至少一条官方直连备份;每月复盘积分毛利表,毛利跌破 50% 的模型立即调价或下架。
- **订阅的现实**:支付宝/微信周期代扣资质极难拿,前期就是"手动续费/对公打款+到期提醒",不要把"自动订阅"写进承诺。API 计量 6–12 月再说。
- **收钱的前提**:工作室版卖"子账号权限",但 team 页现在是 redirect 占位——最简两级角色(管理员/成员+账号可见范围)必须进 0–3 月,否则矩阵版以上收不了钱。

### 6.3 冷启动:第一批 100 个付费客户

① 创始人做"TikTok 矩阵实操"内容(抖音/视频号/公众号),**用 Star Gaze 自己量产演示内容**(狗粮即 demo),评论区导微信群;② 出海社群地推(生财有术/TK 圈/深杭跨境线下会),找 10 个矩阵团队免费用 3 个月换深度反馈+可公开案例;③ 代运营反哺仅在现金流紧张时启用,**上限 3 单**。路径:②换 10 个种子 → 打磨到续费 >60% → ①放大到 100。**没有续费率就放大 = 花钱买流失。**

## 七、落地路线图(对抗审查修正版)

### 0–3 月:TikTok 矩阵闭环能收钱,风控先于收钱

**目标**:15+ 付费团队在官方 API 限额下真实跑通"生成→矩阵发布→看数据"。

**交付**:
1. **风控最小集(第一优先,先于收第一笔钱)**:先审后发 + 内容相似度去重/强制变体 + 账号级 70% 配额 + 单租户熔断 + AIGC 标注字段默认开启(CommonPublishInput 增加,TikTok/YT/Meta 均强制 AI 内容披露,发布 API 有现成字段);
2. **长周期审批全部前置提交(零工程量)**:YouTube compliance audit、Meta 企业验证 + App Review、TikTok Business API(评论)资质、TikTok Shop 开发者入驻——申请前置,开发照旧后置,否则 3–6 月的多平台指标整个卡在审批队列上;
3. 创作板块收敛:主线=角色→图片/视频工作台→TikTok 发布;隐藏 templates/image-slideshow/meta-publish;viral-clone 解决版权红线后补入口;
4. 最简团队权限(两级角色)+ 订阅档位上线(手动续费);
5. TikTok sync-stats(确认审核状态后打开)+ 每账号播放曲线;
6. 发布稳定性:修掉"env 开关失误把海外任务写成终态 failed"类坑,发布成功率可监控;
7. **限额验证**:3 个真实矩阵团队在官方限额下跑 4 周,数据决定矩阵版定价与账号数门槛;
8. **主体结构 90 天内定案**:香港/美国主体不是"有海外直客再办"的可选项,而是资质容器——开发者账号、broker、隐私政策、(远期)Stripe 统一迁入哪个主体,现在定;
9. 数据表纪律:冻结旧任务表,新功能只写新 posts/jobs 表。

**明确不做**:App、MCP 对外、WhatsApp、提现、评论互动、FB/IG 深耕、消息队列重构、通用工作流引擎。

**验证指标**:15+ 付费团队、月流水 ≥5 万、TikTok 发布成功率 >95%、种子次月续费 >60%(不到 50% 停下修产品)、零平台违规警告。

### 3–6 月:多平台 + 数据看板成为留存钩子

**交付(注意顺序)**:
1. **统一 posts 表先行**,再用 PlatformPublishPage 抽象收编 YouTube(废掉 2356 行独立页)、合并 Meta 三张复制表——收编落点必须是新表;
2. YT/FB/IG 数据回拉 + 账号组聚合看板(四张报表);
3. 评论聚合只读(YT 先行 + IG webhook 落库);
4. cron 轮询加固/换队列(发布量上来后 300s 上限会炸);
5. 统一 Job/Content 模型,内容库上线。

**明确不做**:原生 App(响应式 Web 顶着)、WhatsApp 自动化、MCP 对外、提现。

**验证指标**:100 付费客户、多平台发布占比 >40%、月流失 <10%、矩阵版及以上占收入 >60%。

## 八、红线清单(任何一条踩破都可能直接死)

1. **平台权限连坐**:风控先于收钱;sync-stats 类动作先确认审核状态;宁可功能慢也别丢 audited 权限。
2. **矩阵反 spam**:强制变体做成功能;同内容批量分发按"协同不实"处置是各平台明文政策。
3. **viral-clone 版权/肖像权**:逐段克隆对标爆款是侵权高危,被投诉直接烧开发者资质——限定自有素材+公域参考、模特/角色授权链存证后再放入口。
4. **AIGC 标注**:三大平台均强制披露,批量 AI 带货视频不标注=限流下架连带资质,发布默认开启。
5. **国内合规**:中国主体提供 AIGC 服务的算法/大模型备案、数据出境评估(海外账号 token/用户数据回传境内)——立即做备案路径评估,明确 ToB 工具口径。
6. **群控/逆向方案**:设备农场、云手机、非官方 WhatsApp API 全部违 ToS,可内部实验,**严禁承载付费用户核心链路**。
7. **中转商依赖**:核心模型保持一条官方直连备份 + 同档位两家可切换。
