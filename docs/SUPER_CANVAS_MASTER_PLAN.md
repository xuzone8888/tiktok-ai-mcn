## 一、目标与裁决(用户原话为准)

- **形态**:超级画布(对标 liblib.tv LibTV 画布),自由无限画布 + 卡片节点 + 连线,能真出片。
- **验证目标**:工业级视频生成,满足**剧情创作(漫剧/短剧/小说推文等)**与**电商视频工作室**使用(两者都是目标,不许砍;节奏=电商先行、剧情创作随 P2 跟上)。
- **轨道命名(2026-07-12 用户裁决)**:双轨对外命名=**「电商带货」/「剧情创作」**——剧情轨用内容创作类型命名,不叫「漫剧」(漫剧只是该轨典型场景);**双轨在 UI 呈现上互不渗透**:剧情创作轨界面不出现电商词汇,反之亦然(分镜表按轨列显隐是该原则的第一个落点)。文档群中「漫剧」一词一律理解为场景示例。
- **要求**:易上手易使用;**每个功能交付后使用流程稳定、正常**;LibTV 不相关内容裁掉;积分先搭框架(数值占位/参照 LibTV),后续整体优化;长程任务,一边做一边验证。
- **愿景**:画布是公有的——任何人的画布可分享进来、也可嵌出去,生态融合(→ §八 分享分级)。
- **历史包袱**:v1「全屏导演工作台」方案(artifact 732bdf3c)被画布方向取代;其导演层引擎设计(三器官串联/两段式/幂等重渲)折入脚本节点(§六)。2026-07-11 被否决的 17-agent 方案要点(两抽屉合并/片段卡小画布/2×2 卡片墙)仍不许复活。

## 二、范围:两条黄金旅程定边界(不用「80%」)

范围唯一事实源 = 本节 + §三 三列表 + [SUPER_CANVAS_CHECKLIST.md](./SUPER_CANVAS_CHECKLIST.md)(功能点级)。**判据:凡不在两条旅程关键路径上的 LibTV 功能,默认裁。**

**双轨统一原理(2026-07-12 实测定论)**:管线本质 = **结构化分镜 → 资产装配(保一致性)→ 逐镜生图 → 图生视频 → 配音 → 合成**,起点可换——电商与漫剧只是两种起点节点(商品节点/剧本节点),分镜之后全共用;资产三类(角色/场景/道具)+ 一致性黄金 prompt 是双轨共同底座(电商映射:模特=角色、拍摄场景=场景、**商品=道具资产**)。

- **旅程 A·电商(P1 可走通,≤7 步)**:上传商品图 → 商品节点(卖点解析)→ 图片节点(场景图/商品多角度 nine_grid)→ 视频节点(图生视频)→ 下载 / 直发 TikTok(自动 AIGC 标注)。**P1 以单视频收口(裁决 2026-07-12):合成节点 P3 上线后旅程延长为多镜拼接版;「贴链接」入口 P1 不渲染(解析 P3)。**
- **旅程 B·剧情创作(P2 可走通,≤9 步;覆盖漫剧/短剧/推文场景)**:一句话/剧本节点 → 脚本节点(9 维度分镜表)→ 资产装配(角色/场景/道具,黄金 prompt 设定图)→ 批量生分镜图 → 批量生视频 → 合成 → 下载。
- 每期发布前用真人各走一遍双旅程:记录步数与卡点(停留>60s 无操作=卡点),卡点>2 不发布。

## 四、架构决策(ADR)

1. **底盘 = React Flow(MIT)+ 自研媒体节点 + zustand**。tldraw($6k/年+水印)备选;ComfyUI 前端 GPL 禁抄;自研兜底 6-9 人月不走。媒体策略:节点默认 poster 缩略图,**选中才挂 `<video>`**(DOM 断言进 DoD),同屏活跃视频 ≤6,zoom 低于阈值节点降级色块(语义缩放)。
2. **执行留在现有链路,画布只是编排视图**。铁律:**双轨期画布零 fork 任何 API/执行器/store 原语,出现"必须 fork"即停手上会。**明确:BTM 是**浏览器内**编排器(不是服务端),画布沿用之;**节点执行状态唯一真相源 = 服务端 generations 表**,画布文档只存 `nodeId→taskId/generationId` 引用,BTM 写回仅作乐观 UI。
3. **单写者**:同一画布任一时刻仅一个写者标签(navigator.locks,P0 交付不许推迟),其余标签只读+横幅。
4. **统一对账合约(P1 前置交付物)**:每类节点注册 `{jobKey, fetchStatus(jobKey), pollInterval, terminalTimeout}`;触发点=画布加载/visibilitychange 回前台/手动刷新;超时判死必触发幂等退款。验收:提交后 kill 标签→重开→状态收敛到服务端真值。
5. **画布文档 schema**:`canvases` 表,jsonb 存**拓扑+引用**(nodes/edges/groups + schemaVersion + deps 依赖清单[模型/音色/角色/配方 ID,v1 即有字段可空]);**禁存 dataURL/签名 URL,只存 OSS object key**(渲染层换签名 URL+内存缓存);文档 >512KB 拒存并提示;保存=节点级补丁(op log),非重叠自动 rebase;本地影子副本用 IndexedDB(不占 localStorage 5MB 配额),重载 shadow>server 提示一键恢复。
6. **坏档防御**:加载走 zod 校验,非法节点降级为「损坏节点」占位卡(可删),**永不整画布白屏**;迁移注册表(v1→v2→…),「上一 schema 版本文档能打开」进 DoD。LibTV 实测崩过 React #185——错误边界+恢复按钮照抄,并加 store 层防护(见 §七 性能预算)。
7. **合成/批量类重任务一律 DB 排队**(local-stitch 并发闸=2、3.4G 小机),节点显示排队位,禁止 fail-fast 报错甩用户。
8. **路由**:新 `/canvas`(P0 起),不动 `/studio`。**omnibox 长期保留为轻量快捷入口,画布只收编多节点编排型链路;幻灯片/图文帖明确不进画布 v1**。三库同源(积分/角色/历史),画布「从历史选择」直读现有 generations/assets/blueprints,不建平行表。
9. **收编量化判据**(全满足才改导航,再观察 14 天才可折叠旧入口):画布路径提交→成片完成率 ≥ /studio 同链路;P95 出片时长不劣化;连续 14 天零 P0/P1 缺陷;积分对账抽样 100 单零差异。

## 五、节点规格 v1(6 类白名单)

每个节点统一具备:输入(上游连线/上传/历史选择)、生成器面板(模型+参数胶囊+@引用+积分预估+发送)、状态机(idle→queued→running→done/failed;failed 单独重试;刷新经对账恢复)、产物动作(下载/入库/推为参考/直发)。

| 节点 | 说明 | 后端复用 |
|---|---|---|
| 文本 | 文案/提示词载体,可被 @ 引用;**`story_brief` 变体=剧本节点(漫剧起点)**:结构化故事简报(标题/类型/基调/时长建议/分场),输出落 `blueprints.story`,不占第 7 类白名单 | 无新增 |
| 图片 | 文生图/垫图指令整图编辑;工具条=高清/裁剪/整图重生成/**商品多角度 nine_grid(P1,后端现成)**/**资产九宫格·宫格切分(P2,写入资产参考图)** | /api/generate/image + gpt-image-2 |
| 视频 | 能力矩阵驱动模式(文生/图生/首尾帧…按所选模型渲染);特效/运镜=预设 chips 进参数(P2);**生成音频开关(P2,supportsNativeAudio 能力字段+DTO 参数扩展;开启的镜跳过 TTS)** | models/submit 7 模型网关(零 fork,允许参数扩展) |
| 商品 | 商品图/链接→卖点卡(P1 轻量版=上传图+文本;链接解析 P3)。**双身份规则(P2 进向导时)**:卖点文本→分镜生成的上游输入;商品图→自动创建**道具类资产**(一致性 prompt 保商品外观),分镜 @商品 即引用该资产 | product-vision / parse-reference |
| 脚本 | **= blueprints 的画布宿主**,三步向导(分镜表/资产装配/合成提示词),见 §六 | blueprints + 蓝图抽屉组件级复用 |
| 合成 | 多视频→拼接成片(DB 排队,P3;LibTV 实测该节点纯下游、空态无参数面板);(后期)轮播模式承接幻灯片能力评估 | ai-gen/stitch 双通道 |

灰置控件必须点击可得「如何解锁」指引(如视频节点无上游图:「需要一张图片,[创建图片节点]/[从历史选择]」);所有模式/参数名配一句话人话+悬停示例。

## 六、脚本节点 + 资产装配系统(双轨心脏,P2)

> 数据模型细节(DDL/字段映射/注入链,全部经代码实证)见 [SUPER_CANVAS_DATA_MODEL.md](./SUPER_CANVAS_DATA_MODEL.md)。

- **不重写蓝图编辑器**:双击节点打开现有 blueprint-drawer(组件级复用,不 fork);2026-07-05 刚过人工走查的能力(台词行内编辑/hook 矩阵/配方实例化/卖点勾选)全部继承。宿主形态=三步向导(①确认镜头=分镜表 ②准备资产=资产装配 ③合成提示词→批量出片),对齐 LibTV 实测。
- **分镜表 9 维度**:`blueprints.scenes` jsonb 内演进(不拆行表):现有 idx/line/visual/slot/duration_ms/beat 上加 `shot_size`(景别 10 枚举 chips)/`lighting`/`sfx`(**v1 采集不消费,P4 时间线预留,UI 标注**)/`camera_move`(自由文本+预设 chips)/`compiled_prompt`+`compiled_at`(编译缓存,手改后锁定)/`asset_refs`(@资产结构化引用);`slot` 降格为「主素材槽」加 `scene_frame` 枚举(逐镜分镜图回填)。旧蓝图无新键行为逐字节不变;sanitizeScenes 白名单追加+按 idx 合并保留新键防旧端冲写。**按轨列显隐**:电商轨默认 4 列(镜号/描述/台词/时长),剧情轨 9 列全显;引擎照样全填,用户只改不填。支持添加/删除/复制镜头行 + **行拖拽排序**(四轮实测 LibTV 有)。
- **资产装配系统(双轨一致性底座)**:
  - **三类资产两层结构**:全局库层=角色留 `ai_models`(零 DDL 改动,character-picker→CharacterAssetSnapshot→两网关通道已全通)+ 场景/道具/角色造型变体入新表 `canvas_assets`;蓝图内实例层=`blueprints.assets` jsonb(向导②识别出的待设定资产,生命周期随蓝图,「入库」动作提升为全局行)。生成状态永远查 generations(真相源红线)。
  - **AI 自动识别**:从分镜描述识别资产并归类挂「待创建槽」(LibTV 实测:17 镜识出 4 角色+2 场景+1 道具);每资产三来源(AI 生成/画布选/上传)+「一键生成所有资产」默认按钮。
  - **一致性黄金 prompt 模板化**:代码常量+版本号(`src/lib/studio/asset-prompts.ts`,仿 PRICING_VERSION 模式);角色=4 视图(正面半身特写+全身正面+左侧面+背面,白底棚拍平光+面发体服一致硬约束+负面清单)、道具=6 视图变体、场景=场景卡;变量槽=`{visual_style}`+`{asset_description}`;模板升级不触碰用户改过的描述(`description_edited`+`prompt_template_version` 双字段判定,重生成必须显式确认——设定图花积分,自动跑=偷扣费)。
  - **全局风格统一(一致性命门)**:漫剧=`blueprints.story.visual_style`、电商=`globals.style`;资产设定图与逐镜提示词编译统一尾注 `[视觉风格:X]`,取值序=story.visual_style ?? globals.style ?? 商品默认。
  - **同角色多版本**(现代/唐朝沈昭昭):canvas_assets 兄弟行共享 `character_model_id`+`variant_label`,生成第二版本时用第一版本参考图垫图保脸;ai_models 不动,P3 再评估跨表 variant_group。
  - **@资产引用**:`scenes[i].asset_refs=[{asset_id,alias,asset_type}]` 为真相,visual 文本内 `@alias` 仅作蓝色高亮展示(匹配不到降级普通文本永不报错)——无解析、改名不碎。
  - **逐镜注入(零 fork)**:compiled_prompt 编译=风格头+画面描述+镜头语言(景别/运镜/光影)+逐资产设定块(消毒≤420 字符,复用 getSafeCharacterDescription 口径)+时长尾注;垫图=第一角色走 characterAsset 通道、其余资产设定图走 sourceImageUrls(上游硬上限 16,软上限 8);**一致性主通道=逐镜分镜图(已注入全部资产)→图生视频首帧**,不依赖视频模型垫图能力(seedance/sora2 仅 0-1 张)。视频腿 prompt 优先取 compiled_prompt(AiGenSceneSpec 加 compiledPrompt 可选键,白名单追加)。
- **导演引擎(双轨分流)**:**电商轨=现三器官不动**(deepseek 撰稿+segmenter 气口分段+qwen hooks 四型,已过人工走查);**剧情轨=新增「剧情分镜编排段」**(P2 第一子任务,最大技术风险点):一次 LLM 调用产 N 镜结构化 JSON(9 维度逐镜差异化,json_mode+zod 校验+失败重试消毒),**绕过 segmenter**(其 4 段封顶/电商叙事角色枚举不适配 17 镜剧情节拍),两轨在 blueprints.scenes 汇合;模型先用 deepseek-V3/qwen-max 实测结构稳定性,不追 GVLM。**两段式**继承:机械稿即时呈现(零白屏)→导演稿异步 diff 覆写,每镜可还原;导演稿免费(入 usage 流水+滥用闸:每用户 50 次/日、单蓝图免费重生成 5 次,超出按脚本生成价)。
- **门控软化**(对电商用户):「资产不齐」默认走自动生成/可跳过,只警示「哪些镜会降质」;硬门控仅零输入(LibTV 是硬门控 0/7 灰步③,我方软化)。**批量生视频门控同源**:缺分镜图的镜跳过+警示,不整批卡死。
- **批量体验**:批次进度面板(总进度+逐镜四态格+积分实扣/实退实时数)、失败镜一键单独重试(成功镜不重扣)、节点角标 n/m 常驻;**先试 N 镜**(批量生视频默认勾选前 3 镜试产,满意再全量——漫剧 17 镜≈⚡2300/片 的留存保护);**失败分型**(可重试类显重试钮;内容审核拒类显「改画面描述」直达该镜编辑——漫剧打斗/武器题材高频触发);**批量生分镜图先落库排队**(图片腿无批量网关:批次预创建 generations queued 行+batch_id+spec,BTM 逐镜消化,并发闸 2-3+429 退避,关标签经对账合约恢复)。
- **render_mode 加 `storyboard` 枚举**(P2 第一批迁移,dashboard 执行提前排期):漫剧「逐镜图→图生视频→合成」不是现有三值任何一个;禁止重演 photo_post 落 null 绕过的先例(按 render_mode 分流的对账/批次逻辑会静默漏漫剧腿)。
- **向导中途刷新恢复**:向导步态+已生成资产引用落 blueprints 行(draft 态)而非仅内存,刷新经对账合约恢复(P2 验收模板项的实现载体)。

## 七、易用性与稳定性硬条款

## 八、积分框架(P1 搭好,数值零变更)

**铁律:框架期不新增、不修改任何价目;新节点接入沿用其宿主链路现价**(图片 1K/2K/4K=5/10/15、视频=各模型现价、assembly 1⚡/镜先渲后扣、hook/导演稿免费、拼接=assembly 现价对齐 **不另立 0 价**)。LibTV 参照价仅作后续定价讨论输入(2K图⚡18/Seedance2.0 5s720P⚡135/脚本⚡6;年费四档 499/1299/2999/6599 元)。

- **双模式声明**:每 action 显式 `billing_mode`:`post_charge`(≤5⚡ 内部渲染:拼接/TTS镜,先渲后扣失败零扣费无退款面,与 assembly 既有裁决对齐)/`hold_settle`(**P3 才启用**,大额第三方任务)/`free`(导演稿/hook,入 amount=0 流水+每日配额闸,服务端 429 fail-fast)。
- **P1 交付**:①estimate API(`src/lib/credits/pricing.ts` 单一常量模块导出 `estimateCredits(action,model,params)`,estimate 与结算 import 同一函数;带 `PRICING_VERSION`,提交回传,服务端重算>预估则拒单要求刷新)——**同 PR 收敛散落 4 处的定价**(deduct 路由 CREDIT_PRICING/types VIDEO_MODEL_PRICING/lib/credits.ts@deprecated/actions.generate-video)。②**下线两个无鉴权路由 `/api/user/credits/{deduct,refund}`**(现状:userId 取请求体+admin client 直改余额+deduct 不写流水——安全洞,P1 前必须处理)。③退款幂等下沉 DB:`credit_transactions` 部分唯一索引 `unique(type,(metadata->>'task_id')) where type='refund'`,插入 on conflict do nothing,应用层 check 仅优化。④流水标准化迁移:type 枚举定死(consume/refund/free_usage/grant)+补 task_id/canvas_id/node_id/batch_id/action_id 结构化列+索引,删 insertCreditTransaction 运行时试插循环;用户侧明细页=按 canvas/batch 聚合只读查询。⑤客户端零金额条款:前端只传 action+params+estimateToken,金额与扣费全在服务端任务提交事务里。
- **批量记账(P2 前置)**:批量=1 batch_id + **N 个子任务独立 task_id 独立扣/退**(直扣模式天然支持部分退;禁止单笔 lump deduct);结果条「成功 x/N,已退 y⚡」;流水按镜可查。并发扣费经 Postgres RPC 单语句原子(`UPDATE ... WHERE credits >= amount`),CAS 循环仅留低频路径。
- **hold_settle(P3)**:`credit_actions`/`credit_holds` 表结构 P1 随迁移落库冻结但不启用(防后续迁移);启用前置=悬挂释放(≤10 分钟自动释放)+对账脚本可查任何悬挂单;结算封顶 `settled_amount ≤ estimated_amount`(库级 check),超时长部分平台吸收永不超收;改价只对新预估生效,在途按 hold 锚定 pricing_version 结算。DDL 草案见评审档(planreview-credits)。
