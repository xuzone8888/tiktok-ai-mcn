# TikTok Accounts API organic comments application plan

> Status: preparation only. Do not create or submit an App, submit the Accounts API
> Access Application Form, start real Business OAuth, or enable comment flags without
> a separate approval. The current Developer identity must still show the approved
> Profile, and the permission catalog must load before an App draft is created.

## 1. Capability and permission boundary

The first release requests only:

- **Get Business Comment** — `comment.list`
  - `GET /open_api/v1.3/business/comment/list/`
  - `GET /open_api/v1.3/business/comment/reply/list/`
- **Manage Account Comment** — `comment.list.manage`
  - `POST /open_api/v1.3/business/comment/reply/create/`

It does not request Account User, Get Account Media, Ad Account Management, Ads
Management, campaign, reporting, or Research API permissions. Star Gaze uses video IDs
that already passed its own tenant, normal-account, and published-task ownership checks.

Display API `video.list` is a separate TikTok for Developers approval. Its `comment_count`
is only a video-level aggregate; it does not provide comment text, authors, reply threads,
or reply creation.

## 2. Hard stop conditions

Stop without creating or submitting an App if any condition is true:

- the signed-in TikTok for Business Developer identity does not match the approved Profile;
- **My Apps** is unexpectedly nonzero or shows an App not created in this workflow;
- the permission catalog is empty or displays **No data**;
- a stable HTTPS review origin is not available;
- the public English Terms, Privacy, Contact, and official website evidence are not deployed;
- the Accounts API Access Application Form rules or Portal field labels cannot be read;
- any comment/read/reply feature flag is enabled in Production.

If the permission catalog remains empty after a reasonable retry, open a support ticket and
include only non-sensitive identity anchors and screenshots. Never submit an empty-permission App.

## 3. App draft sequence

1. Record the approved Developer Profile, registered Business account email from Account
   Settings, and `My Apps=0` without exposing private credentials.
2. Establish a stable review hostname and deploy the reviewed build with all comment/reply
   flags false.
3. Prepare two different redirect destinations:
   - **Advertiser redirect URL:** a stable, non-token landing page if the creation form requires it.
   - **TikTok account-holder redirect URL:** exact HTTPS
     `/api/tiktok/business-auth/callback/`, used in the authorization and token exchange.
4. When the permission catalog loads, create one draft and do not submit it. Use a stable,
   production-appropriate App name without “Sandbox”; keep environment details in Description.
5. Select only the two permissions in Section 1. If Portal groups them under a parent product,
   save a screenshot of that dependency and deselect every optional unrelated permission.
6. Save the draft's exact App name and the current Portal field summary.
7. Submit the Accounts API Access Application Form once, using that exact App name,
   the registered Business account email from Account Settings, the truthful Technology
   Company classification, the matching legal entity evidence, and a user-confirmed account
   volume. Do not invent customers, revenue, campaigns, or account volume.
8. Save the form receipt. A changed App name requires a new review of whether the form must be
   resubmitted; do not reuse a mismatched receipt.
9. Perform a final read-only comparison of App draft, permissions, both redirect fields,
   public policies, form receipt, logo, and review recording. Obtain separate approval before Submit.

## 4. Account-holder OAuth after App approval

- Do not guess the authorization URL. Capture the complete URL generated by the approved App
  Detail and verify its fixed HTTPS scheme, host, path, and parameters before configuring it.
- The application may inject only a fresh random state and the two approved scopes. Omitting
  scope may grant all App permissions and is not allowed.
- The account-holder `auth_code` is short-lived and single-use. The callback URI sent during
  exchange must exactly match the Portal account-holder callback, including its trailing slash.
- Store each rotated refresh token returned by TikTok. Tokens never enter browser responses,
  logs, screenshots, or URL filters.
- Login Kit and Accounts API open IDs are app-specific. The UI must instruct the user to authorize
  the same TikTok account selected for publishing; the system must not claim equality by comparing
  those open IDs.

## 5. Prototype/review recording script

Only the script and shot checklist are prepared now. The official recording is made later, after
stable HTTPS staging, the final build, exact Portal permissions, callbacks, policies, and review
account are frozen. Any earlier mock is labeled **Prototype** and must not imply a successful API call.

1. Open the anonymous English website, Contact, Terms, and Privacy pages; show the legal operator,
   Star Gaze brand relationship, official domain, contact channel, and Business comment disclosure.
2. Sign in to the isolated Star Gaze review account.
3. Show separate “publishing/video authorization” and “comment authorization” states.
4. Select a normal publishing account and explain that the same TikTok identity must be chosen in
   the independent account-holder consent.
5. Show consent for only Get Business Comment and Manage Account Comment.
6. Return through the exact trailing-slash callback without exposing its query string.
7. Open a previously published task video and synchronize top-level comments and reply threads.
8. Show bounded pagination, truncated/incomplete messaging, and safe retry after a read rate limit.
9. Enter a reply and explicitly submit it; show that no automatic or bulk reply is sent.
10. Repeat the same idempotency key/recovery scenario and show no duplicate provider write.
11. Use **Disconnect Comments**; show publishing authorization and tasks remain connected while
    Business comment access is blocked/revoked.
12. With rollout flags closed, show that an existing active, expired, or incomplete comment connection
    remains visible and independently disconnectable.
13. If a remote revoke response was lost, show that no second provider call occurs; confirm revocation in
    TikTok settings, then use the audited local-completion action.
14. Show missing-permission, wrong-account instruction, no-data, and provider-unavailable states.

Do not record a client secret, token, authorization code, full state, phone number, private email,
provider request body, Authorization header, or unrelated user content.

## 6. Staged functional acceptance

After App approval and credential delivery, keep Production flags false and use isolated staging:

1. readiness passes against the actual process environment and exact stable callback;
2. account-holder OAuth and token rotation pass with `comment.list` and `comment.list.manage` only;
3. comment list and reply-list pass before reply creation is enabled;
4. shared account+endpoint budgets cap reads across instances and preserve a resume cursor;
5. 429/5xx/network GET failures retry only within the reserved budget and respect Retry-After;
6. reply/create is never blindly retried after an ambiguous result;
7. 1201 Unicode code points are rejected before action-log/provider dispatch;
8. foreign, Shop, arbitrary video, and wrong-tenant targets fail before credential/provider access;
9. independent disconnect and `revocation_pending` recovery pass without deleting publishing data;
10. an account-level generation fence prevents an OAuth attempt that started before disconnect from
    committing after revocation begins, and blocks reauthorization while revocation is pending;
11. logs, errors, screenshots, and recordings contain no credential material.

Production read, reply, and disconnect capabilities are enabled as separate rollout gates only
after their corresponding staging evidence is reviewed.
