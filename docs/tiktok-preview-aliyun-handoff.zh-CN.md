## A. 同事负责：阿里云侧

### A1. 不依赖应用代码的准备项

1. 创建独立测试 Bucket，名称建议 `toryx-tiktok-preview-test-<唯一后缀>`；如冲突自行换后缀并回填实际名称。不要复用公开媒体/CDN Bucket。

3. Bucket ACL 必须为 private；不配置公开访问策略、公共 CDN。当前实现要求不存在 Bucket Policy，版本控制从未启用（不是先启用再暂停）。若账号强制策略不符合要求，停止并反馈，不要为通过检查降低安全性。

此阶段回传实际 Bucket 名称、地域、ACL/Policy/Versioning 和匿名拒绝检查结果。不要删除已有 Bucket 来纠正配置；如误配，先反馈。

版本控制误开后不要擅自删桶：可以在授权范围内另建不同名称、从未启用版本控制的测试桶，原桶另行核实内容与用途后决定是否删除。

匿名探针可从无凭证的客户端请求真实 OSS endpoint 的 Bucket 根路径及一个不存在的对象键；使用 `curl -q` 避免加载默认 curl 配置，不带 Authorization、Cookie 或签名查询参数，不跟随跳转。记录 HTTP 状态及 OSS XML `Code`。`403 AccessDenied` 只能证明该次请求被拒，不能单独证明所有对象安全；`404 NoSuchKey` 不算验收通过，也不单凭它断定整个桶公开。意外的 200、重定向、网络错误或其他错误码应暂停核查。实际测试对象上传后还须验证匿名读取被拒，并结合 ACL/Policy/Versioning 检查综合验收。无对象探针不能替代实际对象验收。

- 匿名 OSS 读取被拒绝；Bucket ACL/private、无 Policy、无 Versioning 检查通过。

- 在专门的可删除测试任务上验证删除队列与实际文件清理；不要拿真实业务任务测试删除。
- ready 媒体没有一小时自动过期；临时读取签名过期会在下次请求重新签发。删除任务/账号数据后按清理流程删除文件。
